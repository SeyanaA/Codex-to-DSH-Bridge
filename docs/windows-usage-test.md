# Windows 使用与测试指南（0.1.0-preview.1 预览版）

这份文档是给你在**自己的 Windows 电脑上**照着做的测试步骤，不是"Windows 已经测过、肯定没问题"的结论。

一句话说明现状：

- 版本是 **0.1.0-preview.1 预览版**，属于"已经打包好、还没做实机验收"的阶段。
- **Windows 的 EXE 只在本地提供**（本轮随包一起给），**没有放进当前的 GitHub Release**。Release 页面现在主要是 Mac 的 DMG。
- 这台做打包的 Mac 上**没有发现 Windows 虚拟机，也没有 Wine**，所以我们**没有在真正的 Windows 上运行过**，不能说"Windows 已通过实机测试"。
- Mac 上的实际检查结果见[封装检查报告](windows-package-check.md)。能解包不代表 Windows 上的快捷方式已经验证。

另外几条要先记住：

- **网页里的会话 ≠ DSH Desktop 的会话。** 你在 `http://127.0.0.1:3080` 网页里看到的会话，不会自动出现在 DSH Desktop 里，换端口也搬不过去。
- 这个程序**不会自动创建 git worktree**（独立的工作目录副本）。派给 DeepSeek 的任务，最好先由 Codex 准备好单独的工作区。
- 安全底线：**不要杀掉不认识的 node 进程**，**不要删掉全部配置**，**不要把 key / token 贴到任何地方**（日志、截图、Issue 都不要）。

---

## 一、开始前要准备什么

装之前，Windows 上要先有这些东西：

| 需要的东西 | 说明 |
| --- | --- |
| Node.js 24 或更新 | 启动器会检查版本，低于 24 会直接报错 |
| DSH CLI | DeepSeek 的命令行工具 |
| pnpm | 安装 DSH 插件时用它下载依赖 |
| Codex | 用来把任务交给 DeepSeek |
| 已在 DSH 里配好的 DeepSeek 模型 | 模型凭据由你现有的 DSH 管理，**不用也不要把 key 填进这个程序** |

装依赖可以看 [Node.js 官网](https://nodejs.org/en/download)、[DSH 说明](https://github.com/deepseek-ai/deepseek-harness)、[pnpm 安装说明](https://pnpm.io/installation)。

**先做一次只读检查**（在 PowerShell 里跑，都是只读命令，不会改任何东西）：

```powershell
node --version
Get-Command node,dsh,pnpm
Get-NetTCPConnection -LocalPort 3080 -State Listen -ErrorAction SilentlyContinue
```

怎么看结果：

- `node --version` 要显示 `v24.x` 或更高。
- `Get-Command node,dsh,pnpm` 三个都应该能列出路径；哪个报错就是哪个还没装/没进 PATH。
- 最后一条没有输出，一般表示没有找到监听记录；如果命令不可用或检查被限制，也可能查不到，不能据此认定端口空闲。有输出时先弄清楚服务是谁启动的。

> 除了上面这几条，**不要**自己额外跑清理、杀进程、删配置类命令。这台机器上还有别的程序。

诊断日志位置（出问题时用）：

```text
$env:USERPROFILE\.codex-to-dsh-bridge\service.log
```

只看不改：

```powershell
Get-Content -Tail 20 -Path "$env:USERPROFILE\.codex-to-dsh-bridge\service.log" -ErrorAction SilentlyContinue
```

## 二、测试怎么做

从轻到重，一步一步来。**每一步都先做完操作，再看"应该看到什么"**，然后在本页的记录表里打勾。前一步没过，就先别急着做下一步。

### 准备：安装快捷方式

**操作**

1. 双击本地提供的 EXE 安装器。
2. 一路按提示走，保持默认安装位置即可（装到当前用户目录，不需要管理员权限）。
3. 装完看**桌面**和**开始菜单**。

这份预览 EXE 没有 Windows 代码签名。如果系统拦截，先核对文件来源和[检查报告](windows-package-check.md)中的 SHA-256；不要为了安装它关闭系统防护。若公司电脑不允许安装，把提示记录下来即可。

**应该看到什么**

- 桌面出现一个 "Codex-to-DSH Bridge" 快捷方式。
- 开始菜单里出现一个 "Codex-to-DSH Bridge" 文件夹，里面有：
  - `1 安装与配置`
  - `2 启动 DSH Web`
  - `打开网页`
  - `停止本程序的服务`
  - `诊断`
  - `使用说明`
- Windows"设置 → 应用"里能看到 "Codex-to-DSH Bridge Preview"，版本 `0.1.0-preview.1`。

> 预期是**从安装器设计上应该出现这些**，不是我们已经验证过的结果。少了哪个就记下来。

---

### 第 1 步：诊断（最轻，先看环境齐不齐）

**操作**

1. 开始菜单 → "Codex-to-DSH Bridge" → **诊断**。
2. 会弹出一个命令行窗口，等一下让它跑完。

**应该看到什么**

窗口里逐行列出：

- `Node.js：` 你的版本号（24 以上）
- `DSH CLI：` 找到的路径
- `pnpm：` 已找到 / 未找到
- `本程序配置：` 未安装（这一步还没装，正常）
- `Codex 配置：` 存在 / 不存在
- `3080：` 未监听（正常）
- `本启动器服务：` 未运行（正常）
- `日志：` 日志文件路径
- 最后一行会明说：模型连接和任务执行这项诊断**不做探测**，要你自己实机验收。

做完可以关掉窗口。

---

### 第 2 步：安装与配置

**操作**

1. 开始菜单 → **"1 安装与配置"**。
2. 等它跑完。这一步会联网下载插件依赖，可能慢一点。
3. 看窗口里的最后一句话。

**应该看到什么**

- 过程中有"正在为 DSH Web 安装固定版本的 Crew 插件……"之类的提示。
- 最后提示安装配置完成，并要求你**完全退出并重新打开 Codex**。
- 如果缺东西，它会直接告诉你（比如缺 Node.js、缺 pnpm、Node 版本太低、Codex 里已有另一份 `dsh-crew` 配置），**不会偷偷升级你现有的 DSH**。报错就停下，按提示处理，别硬来。

---

### 第 3 步：完全退出并重开 Codex

**操作**

1. **完全退出** Codex（关窗口不算，要在托盘/任务管理器里确认进程真的没了）。
2. 重新打开 Codex。

**应该看到什么**

- Codex 正常启动，能正常聊天。
- Codex 这时已经带上了新的连接配置和委派规则（第 6 步才会真正用到）。

**注意**：如果安装前你的 DSH Web 本来就在跑，安装插件**不会替你重启它**。需要你自己挑时间重启，插件才会生效。

---

### 第 4 步：启动 DSH Web

**操作**

1. 开始菜单 → **"2 启动 DSH Web"**。
2. 等命令行窗口出结果，浏览器会自动打开 `http://127.0.0.1:3080`。

**应该看到什么**

- 窗口提示服务就绪；最多等到 75 秒，超时会提示去看诊断和日志。
- 浏览器打开 `http://127.0.0.1:3080`，能看到 DSH 的网页界面。
- 这个地址只允许在本机打开，别的电脑访问不了，这是设计如此。
- 如果 3080 已经被**别的服务**占用，它会直接报错并告诉你，**不会去关别人的服务**。
- 如果 3080 上已经是一个能确认身份的 Crew 网页，它会**直接复用**，不再另起一个。
- 要是复用别人启动的 Web，可能需要按 DSH 的提示自己登录。

---

### 第 5 步：重复启动，以及关掉终端窗口后再看

这一小步查两件事：重复点会不会起两份服务；关掉那个命令行窗口后网页还在不在。

**操作**

1. 再点一次"2 启动 DSH Web"。
2. 然后把那个命令行窗口**直接关掉**。
3. 回到浏览器刷新页面；也可以再点开始菜单的 **"打开网页"**。

**应该看到什么**

- 重复启动：不会冒出第二个服务，不会报"端口冲突"，还是同一个网页。
- 关掉终端窗口后：网页**仍然可以正常打开和刷新**（服务是后台跑的，不靠那个窗口活着）。如果关掉窗口网页就挂了，这是问题，记下来。
- 如果网页打不开，"打开网页"会提示 Crew Web 尚未就绪，让你先启动。

---

### 第 6 步：让 Codex 转交一个"最小任务"给 DeepSeek

这一步是**省 Token 的关键测试**：只让 DeepSeek 回一句话，别的什么都不做。

**操作**

1. 在 Codex 里发一段明确的话，比如直接说：

   > 先由你准备一个临时空目录作为工作区，不要用我的真实项目。通过 dsh-crew 把下面这个任务交给 DeepSeek：只回复"Windows 联通测试完成。"这一句话。不要读写文件，不要调用工具，不要搜索，不要查看目录，不要总结。回复完就结束。你负责记录任务编号，并取回回复；不要由你代替 DeepSeek 回答。
   >
   > **请把这句话原样放进给 DeepSeek 的任务里。**

2. 然后就等，别催。

**应该看到什么**

- Codex 会走 `dsh_spawn_worker` 把任务派出去（它会自己处理，你只要看结果）。
- 任务在 DSH 网页的 **Crew 面板**里能看到（见下一步）。
- DeepSeek 的回复就是那句话：**Windows 联通测试完成。**
- 不该出现文件改动、工具调用、搜索行为。如果它自己加戏了，说明约束没传到位，把当时发给 Codex 的原话记下来。

**为什么这么设计**：只回一句话可以减少额外工作和 Token 消耗；加上网页任务记录和 Codex 取回结果，才能确认消息来回都通了。模型仍会处理必要的系统指令，并不是只计这一句话的费用。

---

### 第 7 步：在 Crew 面板看到同一个任务，Codex 拿到结果

**操作**

1. 打开 `http://127.0.0.1:3080`，找到 **Crew 面板**。
2. 对照第 6 步派出去的那个任务。
3. 回到 Codex，等它把结果取回来。

**应该看到什么**

- Crew 面板里能看**同一个任务**的记录和状态。
- 任务状态会从进行中变成完成；如果它需要你补信息，状态会显示 `needs_input` 并停下来等你，你补完再重新派发即可。
- Codex 侧最终能拿到结果，并且会和你说清楚它收到了什么。
- 如果你在 Crew 面板里的会话和 DSH Desktop 里看到的对不上，这是**正常**的，两者本来就不是一回事。

---

### 第 8 步：停止本程序的服务，再启动一次

**操作**

1. 开始菜单 → **"停止本程序的服务"**。
2. 等窗口提示。
3. 再点 "2 启动 DSH Web"。

**应该看到什么**

- 停止时：提示"已请求停止本启动器创建的 DSH 服务"。
- 如果这个服务不是它启动的，它会说"没有找到由本启动器管理的运行服务；没有停止其他 DSH"。**它只停自己拉起的那一个**，不会去动别人的 DSH，这正是预期行为。
- 再启动后：网页又能打开，能正常用。
- 顺便验证一下：停止的是服务本身，**不是**把配置删了。

---

### 第 9 步：卸载，确认配置和备份还在（可选，全部用完再做）

**操作**

1. 先确认服务已经停了。
2. 从 Windows"设置 → 应用"，或安装目录里的 `Uninstall.exe` 卸载。开始菜单没有单独的卸载快捷方式。
3. 卸载过程中会弹一个确认框，问你是否继续。
4. 卸载后检查配置和备份。

**应该看到什么**

- 弹窗里明确写着：卸载**只删程序文件和快捷方式**，Codex/DSH 的配置和备份会保留，需要你自己检查后决定要不要恢复。
- 卸载后：桌面快捷方式和开始菜单文件夹消失，安装目录被删掉。
- 配置和备份**仍然在**：Codex 的 `%USERPROFILE%\.codex\config.toml` 及其 `.backup-*` 文件、DSH web profile 下的备份都还在。
- 这一步的用意就是**确认卸载是"保守"的**：它不会顺手把你原来的配置抹掉。

注意：保留的 Codex 配置中仍会有 `dsh-crew` 连接，卸载程序文件后这条连接就指向不存在的位置。要彻底停用，请在确认备份后，只移除本程序添加的连接段和委派规则；不要删除整份 Codex 配置。如果安装后还改过其他设置，不要直接用旧备份覆盖新设置。DSH 插件仍会保留，卸载 EXE 不等于卸载插件。

只读确认（不改任何东西）：

```powershell
Test-Path "$env:USERPROFILE\.codex\config.toml"
Get-ChildItem "$env:USERPROFILE\.codex" -Filter "*.backup-*" -ErrorAction SilentlyContinue | Select-Object Name
```

## 五、这份文档的边界

- 这里写的是**应该发生什么**，不是"我们在 Windows 上跑出来过什么"。这台 Mac 没有 Windows 虚拟机也没有 Wine，**Windows 实机结论必须由你这次测试来产生**。
- Windows EXE 是本地提供的预览件，**不在当前 GitHub Release 里**。
- EXE 文件完整性、脚本语法与受控本机检查见[检查报告](windows-package-check.md)。开始菜单、桌面快捷方式、Windows 启停仍待你实测。
- 诊断**不做**模型探测：模型能不能连、任务能不能跑，只有第 6、7 步这种实机操作才算数。

PowerShell 只读检查参考：[微软端口查询说明](https://learn.microsoft.com/en-us/powershell/module/nettcpip/get-nettcpconnection)、[微软文件校验说明](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.utility/get-filehash)。
